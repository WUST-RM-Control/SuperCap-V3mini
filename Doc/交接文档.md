## 0. 一句话说清这是什么

一块 RoboMaster 超级电容（能量缓冲）控制板，串在**电管**和**底盘**之间，用四开关 Buck-Boost
把电容组挂在中间，目标是**从电管恒功率取电**、用电容削峰填谷，让裁判系统的缓冲能量不归零（不扣血）。

```
   电管(功率计) ──REF──► [超电控制板] ──CHA──► 底盘电机
                              │
                              B ──► 超级电容组
```

**当前状态：控制软件重写（P0）已完成并通过静态验证，编译 0 Error / 0 Warning。**
剩下的 P1~P9 全是**硬件在环验收**，需要台架数据——这是当前唯一的阻塞点。

## 3. 三条铁律

### 铁律 1：能在 `.ioc` 里配的，一律配在 `.ioc`

不要只改生成代码——重新生成会被静默改回默认值。当前 `.ioc` 已覆盖：

- HRTIM 死区（`RisingValue/FallingValue=10`、`PrescalerDead=MUL4`，实际 14.7 ns）
- I2C1 时序（`Timing=0x20824349`，400 kHz）
- NVIC：控制节拍 `DMA1_Channel1`、全部优先级
  （`ADC1_2/ADC3/ADC4` 的中断使能仍留在 `.ioc` 里，但 ADC 模拟看门狗已取消，这几路中断不会触发）

**进不了 `.ioc` 的只有 3 项**（原因见 AGENTS.md）：I2C 引脚内部上拉、HRTIM 比较值预载、
ADC DMA 长度（运行时参数）。

### 铁律 2：参数只有一个来源

改阈值/限流/环参数 → **只改 `App/params.h`**。改完必须跑：

## 6. 已知风险（别当成 bug 去"修"）

| # | 项 | 说明 |
|---|---|---|
| **R1** | **板上没有 26.5 V 硬件钳位** | 电容侧 TVS 是 `D13 = SMCJ33A`（33 V），对 26.5 V 无效 ⇒ 超压保护全靠固件。强烈建议下一版加 26 V TVS 或比较器接 HRTIM FAULT |
| R2 | CAN_RX 挂 100 nF | 与 1 Mbps 不相容，**待示波器确认**（可能是画错） |
| R3 | PB8 = BOOT0 接 OLED SCL | 模组若带上拉，复位可能进 Bootloader |
| R4 | `VREF+`(3.300 V) 可能高于 `VDDA`(3.3 V±2%) | 违反 `VREF+ ≤ VDDA` |
| R5 | 电压通道带宽仅 175 Hz | 9.1 kΩ+100 nF，靠电流环吸收 |
| R6 | 倒灌峰值 −286 W / 0.24 ms | 电感电流斜率物理限制，能量仅 41 mJ |
| R7 | 400 W 阶跃削不干净 | 15 A 电容限在 19 V 只有 285 W（物理极限） |
| R8 | 电容充满后输入功率必然回落 | 满电无法吸能，属预期 |
| **R9** | **死区预分频必须用 `MUL4`**（2026-10-27 实测确认） | ST 在 HAL 1.2.6→1.2.7 把 `HRTIM_TIMDEADTIME_PRESCALERRATIO_*` 的宏值对调过。实测 `DIV8` = **47 ns/计数** → 10 计数 = **470 ns**，把 A 桥 5%（147 ns）的导通窗口整个吃掉 ⇒ 示波器看到「AH 没信号、AL 只有 70%」。已改 `.ioc` + `hrtim.c` 为 **`MUL4`**（1.47 ns/计数 → 14.7 ns），`check_params` A23 现在会校验这一项 |

## 7. ⚠ 已经被推翻过的结论（别重复踩）

这些是我在这个项目里**先写进文档、后来被数据/规则推翻**的结论。如果你重新推导，很可能得到同样的错误答案。

| 曾经的说法 | 真相 |
|---|---|
| "旧固件能量环符号反了，应改成 `Max + Δ`" | **错**。`Power_Buff_Energy` 是**裁判的缓冲额度**（取超扣减、取少回涨），所以"缓冲低 ⇒ 少取电"是对的，旧代码 `Max − Output` 方向正确。我在 v1.0 里误判并已撤回 |
| "INA240 量程 ±19.4 A，保护设 18 A" | 只对负向。**正向受 `VS−0.2V=3.1V` 限制，只能测到 18.1 A**（worst 16.9 A），18 A 保护点会落在摆幅边缘而失效 ⇒ 已改 **16.5 A** |
| "26.5 V 物理极限 → 直接关断 PWM" | **会死锁**：关断后 1 A 泄放也停了，电压卡在 26.6 V 永远解不开。正确做法：26.5 V 只锁存 + 继续泄放，**26.8 V 才关断**（仿真 K5 已证） |
| "AWD 在 OPAMP 起来后再配，防止误报" | 顺序对但**位置错**：`HAL_ADC_AnalogWDGConfig` 只在"无转换进行中"才真正写寄存器，ADC 连续转换后会**静默跳过**。必须**在启动 DMA 之前**配，并回读 `ADC_CFGR.AWD1EN` 确认 |
| "死区加到 30 ns 保平安" | 过量。按器件参数算是 **≈10 ns 需求 → 取 14.7 ns（10 计数）**；理想程度下 30 ns 只多花 0.12 W，代价是占空比范围少 1% |
| "倒灌判据是 `P_A < 0`" | **错**。电容给底盘放电时 `P_A < 0` 是正常的。倒灌是 `P_Ref = P_Cha + P_A < 0`，限幅要写 `P_A ≥ −P_Cha − 40W`，且**用瞬时 `P_Cha`**（用滤波值会因滞后放过卸载瞬态） |
| "PI 写成 `u += Kp*e` 就行" | 那是双积分，实测超调 **+80%**。必须增量式 `u += Kp*Δe + Ki*e*Ts` |
| "`if (IsrTick < 0xFFFF) IsrTick++;` 防溢出更稳当" | **灾难性错误**（2026-10-27 上机实测）：计数器饱和后值不再变化，1 kHz 心跳把它当成"节拍丢失"，**上电 3.08 s 后必锁 `FLT_TICK` → `ST_FAULT`，PWM 永远不使能**。心跳只看"变没变"，直接 `IsrTick++` 让它自然回绕 |
| "传感器合理性单拍判、永久锁存最安全" | 上电瞬间 ADC/运放未稳、母线悬空时码值贴 0，**首次上电就锁死 `FLT_SENSOR`**（实测必现）。现在改：`SEN_GRACE_MS` 宽限 + 持续 `SEN_TRIP_MS` 确认 + Enable 上升沿可清；真坏了的传感器 200 ms 内会重新锁上 |
| "ADC 模拟看门狗（AWD）做最快一级过流保护" | 已废弃（2026-10-27）：它只能在"无转换进行中"时写入，时机稍错就**静默失效**（实测回读 `AWD1EN=0`），且阈值不能带回差。改用 21.25 kHz 软件限流（`I_LIM_SOFT` 压制 + `OC_TRIP_TICKS` 拍确认后跳闸） |

## 8. 给接手 AI 的操作须知（都是踩过的坑）

1. **不要在 PowerShell 里用 `Set-Content` 改源码**——会把 UTF-8 中文写成系统 ANSI，导致文件损坏。
   改文件用编辑工具；批量替换写成 Python 脚本跑（`io.open(..., encoding='utf-8')`）。
2. **`UV4.exe` 必须 `Start-Process -Wait`**，`&` 调用不等待且 `$LASTEXITCODE` 为空。
3. **`.ioc` 的行内分隔符是转义的 `\:`**（Java properties 格式），
   例如 `NVIC.DMA1_Channel1_IRQn=true\:0\:0\:false\:false\:true\:true\:true\:true`。写错会导致 CubeMX 解析失败。
4. **CubeMX 重新生成后必查 5 项**（这套流程已经验证过一次，见 git 里 `Core/` 的改动）：
   `main.c` 是否还调 `App_Init/App_Loop`、`main.h` 是否还包含 App 头、
   `hrtim.c` 死区是否 10、`i2c.c` 时序是否 `0x20824349`、`it.c` 的 4 个入口有没有重复定义。
5. **看 `.ioc` 的 NVIC 段**：如果没有 `DMA1_Channel1_IRQn`，控制环**一次都不会跑**（这个坑真实存在过）。
6. 涉及 **26.5 V / 15 A / 18 V** 这些数字时，先回到 `params.h` 与设计文档 §8，别凭直觉改。
7. **不要执行 `git commit`**——用户自己在 VS Code 里 review 后提交（见 AGENTS.md §7）。

## 11. 接手后建议的第一件事

如果你没有硬件，能做的只有三件：

1. 跑 `Tools/check_params.py` 和 `Tools/sim_ctrl.py`，确认 23/23 与全部通过；
2. 读 `App/ctrl_core.c` 与 `App/modulator.c`，把设计文档 §5、§7 的公式和代码逐行对照一次；
3. 如果要改任何东西，先想清楚它是"`.ioc` 能配的"还是"只能写在 `App/` 的"，再动手。

如果你有台架，从 **P1** 开始：烧进去，看串口 `Awd` 是否为 1、零点是否 <50 mA，然后贴一段 CSV。
有了这段数据，P2~P6 的推进会很快。
