# SuperCapV3 - Mini 超级电容能量缓冲控制器

基于 **STM32G474RETx** 的 RoboMaster 超级电容（能量缓冲）控制板固件。

板卡串在**电管**与**底盘**之间，用四开关 Buck-Boost 把电容组接在中间：

```
   电管(功率计) ──REF──► [超电控制板] ──CHA──► 底盘电机
                              │
                              B ──► 超级电容组
```

**控制目标：从电管恒功率取电**（`P_Ref → P_Limit`），多余的电存进电容组，底盘需要超额功率时由电容组放电补足 —— 削峰填谷。

为什么"恒功率"是关键：裁判系统按 `dE_Buff/dt = P_Limit − P_Ref` 记账，只要 `P_Ref == P_Limit`，缓冲能量**永不消耗**，扣血在物理上被排除。

> 设计依据、参数推导、仿真验证见 [`Doc/开发文档-控制软件重写.md`](Doc/开发文档-控制软件重写.md)。
> 网表解读与硬件疑点见 [`Doc/SuperCapV3-Mini_网表与控制算法分析.md`](Doc/SuperCapV3-Mini_网表与控制算法分析.md)。

## 2. 硬件平台

### 2.1 功率级

- `Q9–Q12` BSC066N06NS（60 V/6.6 mΩ），`L2` 10 µH（XAL1510），`U4/U5` UCC27282 半桥驱动
- 栅极非对称驱动：开通 3.3 Ω，关断经 1N4148 旁路
- A 侧（电管/底盘侧）母线 `A_POWER`、B 侧（电容侧）母线 `B_POWER`，各 470 µF + 3×10 µF

### 2.2 采样链

| 量 | 采样点 | 引脚 | 通道 |
|---|---|---|---|
| `V_A` | A 侧母线 11:1 分压 | PA3 | ADC1 / OPAMP1 |
| `I_A` | **R6** 4 mΩ（变换器 A 侧电流） | PA7 | ADC2 / OPAMP2 |
| `I_Ref` | **R77** 4 mΩ（电管输出电流） | PB0 | ADC3 / OPAMP3 |
| `I_B` | **R79** 4 mΩ（电容组电流） | PB13 | ADC4 / OPAMP6 |
| `V_B` | B 侧母线 11:1 分压 | PB14 | ADC5 / OPAMP5 |

`CHA` 抽头正好在 R77 与 R6 之间，所以 `I_Cha = I_Ref − I_A` 由**两个同规格分流 + 同增益放大器差分**得出，零点与增益误差大部分对消。

**量程限制**：4 mΩ × 20 V/V = 12.5 A/V，零点 1.65 V。ADC 满量程 ±20.6 A，但 INA240 正向输出只能到 `VS−0.2V=3.1V`，**正向实际只能测到 18.1 A**（worst case 16.9 A）。所以过流动作点放在 **16.5 A**，不是 20 A。

### 2.3 电流重构

由电荷平衡 `I_A = D_A·I_L`、`I_B = D_B·I_L`：

```c
I_L = 0.5f*(I_A/D_A + I_B/D_B);   // 双路平均，模式无关，可互为冗余
```

## 3. 控制原理

### 3.1 三层级联

```
缓冲环  166 Hz    P_Tgt  = clamp(P_Limit − KP_E·(55 − E_Buff), 0, P_Limit + 5)
功率环  21.25 kHz P_A_ref = P_Tgt − P_Cha_f + Trim        ← 死拍前馈（负载扰动一步抵消）
                  Trim'   = 2π·5·(P_Tgt − P_Ref_f)        ← 慢积分，只修损耗/标定残差
电流环  21.25 kHz du = Kp·Δe + Ki·e·Ts;  u += du          ← 增量式，限幅作用在状态上
```

- **`P_Cha_f` 是前馈核心**：`P_Ref = P_Cha + P_A`，所以 `P_A_ref = P_Tgt − P_Cha` 就是"把负载扰动一步抵消"。负载阶跃时输入功率偏差实测 < 1%，不需要等积分追。
- **`P_OVER = 5 W`**：允许小幅超限额取电，用来补偿我们与电管之间的测量误差。稳态下**真实取电恒等于 `P_Limit`**（与测量偏差无关），代价是缓冲停车点偏移 `δ/KP_E`（实测 53~57 J）。
- **缓冲环用 P 控**：被控对象是积分器，P 控即无稳态误差，且没有积分器所以不存在积分饱和。

### 3.2 调制器：`V_L = u·V_A` 恒成立

控制量 `u` 是归一化占空比增量。两个调制器：

```
buck  (r ≤ 1):  D_B = c,        D_A = c·r + u
boost (r ≥ 1):  D_A = c,        D_B = (c − u)/r        (r = V_B/V_A)
```

代入 `V_L = D_A·V_A − D_B·V_B`，**两式都精确得到 `V_L = u·V_A`**。因为是恒等式，任意凸组合也成立，所以用平权混合做无扰切换：

```c
c = DMAX − DH·max(0, 1 − |r−1|/RB);       // r≈1 处下压共同占空比，制造双向裕量
D_A = (1−w)(c·r + u) + w·c;
D_B = (1−w)·c + w·(c−u)/r;
```

这样 `u → V_L` 的增益恒为 `V_A`，与工作点无关，**电流环一组参数覆盖全工况**（旧版变比查表在 `r≈1` 处增益会塌）。

### 3.3 电容电压管理

```
 0 ── 8V ──────────── 25.5 ─ 25.9 ─ 26.0 ── 26.5 ──►
 禁放  正常充放        正常充电  动能回收 超压保护  物理极限
      (taper)         收敛到 0  (不限幅) (1A泄放)  (锁存+泄放)
```

- **动能回收不限幅**：检测到 `P_Cha_f < −2 W`（底盘在回馈）时，充电 taper 从 25.5 放宽到 **25.9 V**，电容满电流吸收动能；留 0.1 V 到 26.0 超压阈值，避免长期贴阈值抖动。
- **26.0 V 超压**：禁止充电 + **主动泄放 1 A**（允许反冲电管/底盘，0.2 V 回差）。
- **26.5 V 物理极限**：锁存，继续 1 A 泄放，**回落到 25.5 V 自动解锁**。

### 3.4 保护

| 故障 | 判据 | 动作 |
|---|---|---|
| 过流限流 | 变换器侧 `max(|I_A|,|I_B|,|I_L|) ≥ 15 A` | **只压制占空比**，< 14 A 自动退出 |
| 过流跳闸 | ≥ 16.5 A 持续 4 拍（≈188 µs），或 ADC 码 ≥3700 持续 2 ms | 关 PWM + 锁存 |
| 母线过压 | `V_A > 32 V` | 关 PWM，`<31 V` 恢复 |
| 底盘离线 | `V_A < 18 V` | 关 PWM，`>19 V` 恢复（电池没电会掉到 19.2 V） |
| 电容超压 / 物理极限 | `V_B ≥ 26.0 / 26.5 V` | 禁充 + 泄放 / 锁存 |
| 控制节拍丢失 | 1 kHz 连续 5 ms 未见控制中断 | 强制关 PWM（节拍恢复自动清除） |
| 传感器失效 | 码值贴边 / 两侧功率不一致，持续 200 ms | 锁存（Enable 上升沿可清） |
| 通信丢失 | 500 ms 无合法帧 | 关 PWM 进 IDLE |

> 过流保护**不用 ADC 模拟看门狗**：它需要在"无转换进行中"才能写入，时机稍错就静默失效（
> 上机实测回读 `AWD1EN=0`）。现在最快一级是 21.25 kHz 软件限流，阈值全在 `params.h`。

同故障 10 s 内 3 次 → 永久锁存（只能断电）。独立看门狗 1 s，**在 1 kHz 中断里喂狗**（主循环卡住不复位），调试器 halt 时冻结。

## 7. 调试

### 7.1 串口工程量（`CFG_DEBUG_UART = 1`，默认开）

USART2 115200，**10 Hz** 一行 CSV：

```
VA,VB,IRef,IA,ICha,IB,IL,PRef,PA,PB,PCha,PTgt,DA,DB,u,VL,uVA,St,Fl,Lim
```

- `St`：状态机（0=INIT 1=IDLE 2=SOFT_START 3=RUN 4=FAULT）
- `Fl`：故障位（hex，见 `protect.h` 的 `FLT_*`）
- `Lim`：软件限流压制中（1 = 当前电流超 15 A，占空比正被压制）

> 上车前把 `CFG_DEBUG_UART` 改成 0。

### 7.2 OLED（10 Hz，主循环刷新）

```
Ref+074.8  Tgt+080.0      电管功率 / 目标
VA +24.01  VB +24.00      母线电压
IA +01.23  IB -00.45      变换器 A 侧 / 电容电流
IR +03.12  IC +01.89      电管 / 底盘电流
PA +074.8  PB -010.8      功率
E  55 J    PL 080         缓冲能量 / 功率限制
DA 0.850   DB 0.850       两桥占空比
 6.2k S3 F00              主循环频率 / 状态 / 故障位
```

**热插拔容错**（`i2c_guard.c`）：板上 SCL/SDA 的上拉在 OLED 模块上，屏一拔总线就悬空。
现在做了三层防护——① 打开 MCU 内部上拉；② 每次传输 1 ms 超时 + 连续 3 次失败判离线，
之后彻底不碰总线；③ 离线期间每 2 s 探测一次（先打 9 个 SCL 时钟做总线恢复 + 外设复位，
再重新 `OLED_Init()`），插回去自动恢复显示。
一帧耗时超过 25 ms 会自动降到 1 Hz 刷新，不拖主循环。
**看门狗改在 1 kHz 中断里喂**，所以 OLED 卡住甚至主循环卡死都不会复位板子。

> 软件只能兜住，根因在硬件：板上 SCL/SDA **没有上拉电阻**（上拉在 OLED 模块上），
> MCU 内部上拉只有约 40 kΩ，400 kHz 下边沿偏慢。下一版建议 PB8/PB9 各加一颗 4.7 kΩ 到 3V3。

## 8. 通信协议（与旧固件逐字节一致）

| ID | 方向 | 载荷 |
|---|---|---|
| `0x30` | 接收 | 3 字节：`Enable_Flag` / `Power_Buff_Energy` / `Max_Referee_P` |
| `0x31` | 发送 | 8 字节 DLC（有效 7 字节）：`State` / `V_Cap×100` / `P_Ref×10` / `P_Cha×10`，均为小端 |

UART：8 字节帧，`Data[6]=0x55`、`Data[7]=0xAA`，前 3 字节同 CAN。

- 通信看门狗：**500 ms** 无有效帧 → 清使能、关 PWM（**不再自复位**，`CFG_RESET_ON_COMM_LOSS` 可还原旧行为）；
- `State` 仍为 0/1，不带故障码；故障看上 OLED / 串口 `Fl`。

## 9. 标定

`calib.c` 按 `HAL_GetUIDw0()` 查表加载：

```
V = raw × (3.3/4096 × 11)  × V_Adjust
I = (raw × 3.3/4096 − 1.65) × 12.5 + I_Adjust
```

未命中 UID 的板子走默认 `1.0 / 0`，电压误差约 ±2%、电流 ±1.2%。新增板卡：读出 UID `w0`，在 `calib.c` 的 `switch` 里加 `case`，用 24 V 标准源和钳表填系数。

## 11. 已知问题 / 风险

| # | 项 | 说明 |
|---|---|---|
| **R1** | **板上没有 26.5 V 硬件钳位** | 电容侧 TVS 是 `D13 = SMCJ33A`（33 V 挡位），对 26.5 V 无效 ⇒ 超压保护**全靠固件**。强烈建议下一版加 26 V TVS 或比较器接 HRTIM FAULT |
| R2 | CAN_RX 挂了 100 nF | 与 1 Mbps 不相容，**待示波器确认**（可能画错） |
| R3 | PB8 = BOOT0 接 OLED SCL | 模组若带上拉，复位可能进 Bootloader |
| R4 | `VREF+`(3.300 V) 可能高于 `VDDA`(3.3 V±2%) | 违反 `VREF+ ≤ VDDA`，建议 VDDA 也由 REF3033 供 |
| R5 | 电压通道带宽仅 175 Hz | 9.1 kΩ+100 nF；靠电流环吸收，想更快可把 C175/C176 改 10 nF |
| R6 | 倒灌峰值 −286 W / 0.24 ms | 电感电流斜率物理限制，能量仅 41 mJ |
| R7 | 400 W 阶跃削不干净 | 15 A 电容限在 19 V 只有 285 W，缺口只能电管直供（物理极限） |
| R8 | 电容充满后输入功率必然回落 | 满电无法吸能，属预期 |
| **R9** | **死区预分频宏被 HAL 换过值** | ST 在 HAL 1.2.6→1.2.7 把 `HRTIM_TIMDEADTIME_PRESCALERRATIO_*` 的宏值对调了，同一宏名在两版下死区差 64 倍。死区由 `.ioc` 配置（`RisingValue/FallingValue=10` + `PrescalerDead=DIV8`），软件层不覆盖；**上车前必须示波器确认约 14.7 ns**，若几乎为 0 就在 CubeMX 里改 `PrescalerDead` |

## 12. 二次开发

- **改控制策略**：`ctrl_core.c` 的 `Ctrl_Step`（三环）与 `Ctrl_Loop_Energy`（缓冲环）；
- **改调制**：`modulator.c` 的 `Modulator_Compute`，注意保持 `V_L = u·V_A` 这个恒等式，否则电流环增益会随工作点漂；
- **改阈值/限流**：只改 `params.h`，改完跑 `Tools/check_params.py`；
- **改环参数**：先在 `Tools/sim_ctrl.py` 里改着跑，确认裕度和阶跃响应再烧板；
- **协议扩展**（如加 CRC）需同步改上位机。
